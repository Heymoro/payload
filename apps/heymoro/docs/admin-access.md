## 入口与账号

- 本地入口：`http://127.0.0.1:3001/admin`，由本应用 Payload 原生后台承载。
- 账号集合：admins；使用后台邮箱/密码及 Payload 管理会话。
- 管理员 admin 与运营 operator 是后台角色，不是小程序业务用户的会员级别。
- 普通用户在 users 集合，使用独立业务会话。即使同一人承担两种身份，也需分别登录；不自动互换 token 或提升权限。

## 权限与责任

| 功能               | 后台管理员                 | 后台运营 | 普通用户                         |
| ------------------ | -------------------------- | -------- | -------------------------------- |
| 后台业务数据查看   | 可按管理权限查看           | 只读     | 无后台权限，仅用户端查看本人数据 |
| 用户/记录/文件管理 | 通过后台与受控接口操作     | 不可写   | 用户端仅本人允许的操作           |
| 后台账号管理       | 可操作，保护最后启用管理员 | 只读     | 不可访问                         |
| 审计记录           | 只读                       | 不可读取 | 不可访问                         |
| 文件物理清理       | 仅管理员受控清理           | 不可执行 | 不可执行，只能提交本人文件删除   |
| 原始身份/会话存储  | 公共入口不开放             | 不开放   | 不开放                           |

用户端的 `/api/v1/me` 不接受管理员 JWT 作为业务用户身份；用户会话也不授予后台权限。后台可以按明确管理权限读取业务数据，不代表它是用户端。

## 自动化证据

`pnpm test:admin-http` 在独立端口和新 SQLite 中验证：

- 首次管理员与最后管理员保护；并发变更及批量拒绝。
- 普通用户对后台账号、审计、身份/会话原始数据访问403。
- 用户及运营执行管理清理403。
- 管理员 JWT 调用用户资料接口401，不能冒充普通用户创建用户端记录。
- 停用/过期会话、批次物理清理与失败重试。

## 仍需人工检查

1. 管理员与运营分别登录后台，逐项检查菜单、列表、表单与操作提示。
2. 清理操作的日常管理界面尚未提供；现有受控 API 及测试不等于完整管理体验。
3. 只在可丢弃的验收数据中验证删除；不自动清理手工开发数据。

上述属于既有本地研发验收范围，不包含生产部署或正式微信账号；当前仍为产品设计评审，人工后台体验尚待验收。

管理功能仅在 Payload Web，小程序保持C端，不新增后台角色页面。

| 主体           | v1列表/元信息/下载  | 原生REST/GraphQL元信息     | 待删除文件管理     |

集合ACL、字段ACL及v1委托已在独立Next+SQLite验证；伪造筛选/hidden/select不能扩大读取；owner更新、原生写入/物理删除权限不因读取开放而扩大。内部上传、附件检查及清理仍使用原有显式权限，不机械取消系统override。

原生文件URL授权后的file-type/webpack 500已在现有Next配置内修复：PDF/JPEG/PNG原生及v1原字节读取通过，PDF另验206/416 Range；Web管理员/运营可读取pending，C端拒绝，清理后原生URL404。此前失败路径现为必须通过的断言，没有另写下载或修改存储。这是当时的验证摘要，结论限本地 Webpack + Node，不代表本次已重跑或已验收新版设计。复验入口见 [验证说明](verification.md)；不将另一个仓库的历史日志作为当前可重复验证的前提。
